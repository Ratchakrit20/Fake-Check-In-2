# Image Relation Inspector

ระบบช่วยตรวจการนำภาพเดิมกลับมาใช้ เช่น ไฟล์ซ้ำ ภาพบีบอัดใหม่ ภาพครอป ภาพเบลอ ภาพกลับด้าน ภาพหมุน 90/180/270 องศา การเปลี่ยนฉาก และการใช้สถานที่เดิมข้ามงาน

ระบบไม่ได้ตัดสินจาก AI ตัวเดียว แต่รวมหลักฐานจาก SHA-256, pHash, SSCD, FAISS, SIFT, RANSAC และโมเดลแยกอวัยวะ พร้อมแสดงเหตุผล ภาพหลักฐาน และ heatmap หลังจัดแนวให้เจ้าหน้าที่ตรวจสอบ

## ระบบทำงานแบบย่อ

```text
รับและตรวจไฟล์
      ↓
SHA-256 ตรวจไฟล์ที่เหมือนกันทุกไบต์
      ↓
SSCD สร้าง embedding เป็น batch
      ↓
ค้น Candidate ขนานกัน 3 ทาง
├─ FAISS Top-K จาก SSCD embedding
├─ pHash 0°/90°/180°/270° ค้นผ่าน BK-tree
└─ SHA-256 เก็บไฟล์ซ้ำตรงตัว
      ↓
รวม Candidate ตัดคู่ซ้ำ และตัดคู่ source เดียวกัน
      ↓
SIFT + RANSAC ยืนยันรายละเอียดและตำแหน่ง
      ↓
organ.pt แยกอวัยวะและแบ่งจุด SIFT ระหว่างตัวบุคคลกับฉากหลัง

Heatmap หลังจัดแนวแสดงพื้นที่พิกเซลที่เปลี่ยนบนคนและฉาก โดยเป็นหลักฐานประกอบและไม่เปลี่ยนคำตัดสินอัตโนมัติ

ภาพเบลอใช้หลักฐาน SIFT/RANSAC ทั้งภาพเป็น fallback แบบเข้มงวด
      ↓
รวมคะแนน → แสดงผล → จัดกลุ่ม
```

ภาพใหม่ที่อัปโหลดภายหลังยังค้นเทียบกับภาพเก่าในคลังได้ ไม่ต้องล้างฐานข้อมูลทุกครั้ง

## ผลลัพธ์หลัก

- **เข้าข่ายใช้ภาพเดิม** — หลักฐานเพียงพอ เช่น ไฟล์เดียวกันหรือภาพเดิมถูกแก้ไข
- **ควรตรวจสอบโดยเจ้าหน้าที่** — พบความสัมพันธ์ เช่น สถานที่เดิมหรืออาจเปลี่ยนฉาก
- **ยังไม่เข้าข่ายใช้ภาพเดิม** — หลักฐานยังไม่เพียงพอ

ผลเป็นเครื่องมือช่วยคัดกรอง ไม่ใช่การยืนยันตัวบุคคลหรือการทุจริตแบบเด็ดขาด

## การรันในเครื่อง (Development)

โหมดเริ่มต้นแยกการทำงานเป็นสามส่วน: React/Vite สำหรับหน้าเว็บ, FastAPI สำหรับ API และ local AI worker ซึ่ง API จะเปิดเป็น process แยกเมื่อมีงานวิเคราะห์ ทั้ง API และ worker ใช้ SQLite ไฟล์เดียวกันตามค่าเริ่มต้น จึงเป็นการแยก process บนเครื่องเดียว ไม่ใช่การแยกฐานข้อมูลหรือการ deploy ข้ามเครื่อง

เปิด terminal แรกที่ root ของโครงการเพื่อเริ่ม API:

```powershell
cd D:\ratchakt\Fake-Check-In-2
conda activate fake-check-in
python -m backend.app.main
```

หากยังไม่เคยติดตั้ง Frontend dependencies ให้รันครั้งเดียว:

```powershell
cd frontend
npm install
```

จากนั้นเปิด terminal ที่สองเพื่อเริ่มหน้าเว็บ:

```powershell
cd frontend
npm run dev
```

ใช้ URL ที่ Vite พิมพ์ใน terminal ซึ่งปกติคือ `http://localhost:5173` และอาจเปลี่ยนเป็น `5174` หากพอร์ตแรกถูกใช้แล้ว ในโหมด development หน้าเว็บเรียก `http://127.0.0.1:8000/api/v1` โดยตรง ตรวจ API ได้ที่ `/health` และเปิดเอกสาร endpoint ที่ `/docs`

เมื่อส่งงานวิเคราะห์ API จะเปิด `backend.app.workers.local_worker` ให้อัตโนมัติ ไม่ต้องเปิด worker terminal เอง งานที่ยังไม่จบจะถูกกู้คืนจาก checkpoint เมื่อ API เริ่มต้นใหม่ และรายละเอียด log อยู่ที่ `output/worker-<job_id>.log` อย่าเปิด API ซ้ำบนพอร์ตเดิม หาก API กำลังทำงานอยู่แล้ว

## ตั้งค่าโดยไม่แก้โค้ด

ค่ามาตรฐานอยู่ใน `config/default.yaml` ส่วนค่าที่ต้องการปรับเฉพาะเครื่องให้ใช้ `.env`:

```powershell
Copy-Item .env.example .env
```

จากนั้นแก้ค่าใน `.env` และ restart Backend ระบบโหลด `.env` อัตโนมัติ ตัวอย่าง:

```dotenv
# เพิ่ม Candidate ต่อภาพ: ลดโอกาสพลาด แต่ประมวลผลช้าลง
VECTOR_SEARCH__TOP_K=50

# เพิ่ม: pHash ยอมรับภาพที่แตกต่างมากขึ้น
PHASH__MAX_HAMMING_DISTANCE=12

# เพิ่ม: RANSAC ต้องมีจุดยืนยันมากขึ้น
RANSAC__MIN_INLIERS=10
```

ข้อควรจำ:

- ค่า ratio/similarity/coverage ใช้ช่วง `0–1`
- เพิ่มค่า `MIN_*` ส่วนใหญ่หมายถึงเข้มงวดขึ้น
- เพิ่มค่า `MAX_*` ส่วนใหญ่มักหมายถึงยอมรับความแตกต่างมากขึ้น
- เปลี่ยนครั้งละหนึ่งค่าและทดสอบหลายประเภทภาพ
- ค่าน้ำหนักคะแนนทั้งสี่ตัวต้องรวมกันเป็น `1.00`
- `.env.example` มีรายการ threshold พร้อมคำอธิบายไทยครบ

## การใช้งานหน้าเว็บ

### Dashboard และรายงาน Excel

Dashboard แสดงกราฟสัดส่วนภาพ กราฟสัดส่วนงาน และรายการเลขงานที่พบการใช้ภาพซ้ำ ข้อมูลระบบจะโหลดใหม่อัตโนมัติทุก 10 วินาที

กรอก “ภาพทั้งหมด” ด้วยตนเอง แล้วกด **ดาวน์โหลด Excel ล่าสุด** ระบบจะสร้างไฟล์จากผลประมวลผลปัจจุบันทุกครั้ง ภายในไฟล์มี:

- กราฟโดนัทสัดส่วนภาพพร้อมเปอร์เซ็นต์
- กราฟโดนัทสัดส่วนงานพร้อมเปอร์เซ็นต์
- จำนวนภาพในระบบและภาพเข้าข่ายใช้ซ้ำ
- จำนวนงานทั้งหมดและงานที่พบใช้ภาพซ้ำ
- Sheet รายการเลขงานซ้ำสำหรับกรองหรือคัดลอกไป PowerPoint

งานนับจากเลข 10 หลักหลัง `home_` หรือ `splitter_` เท่านั้น ส่วน “ภาพทั้งหมด” ไม่มีอยู่ในฐานข้อมูลจึงเป็นช่องกรอกเอง

### เปรียบเทียบสองภาพ

เลือกภาพ A และ B แล้วกดเริ่มวิเคราะห์ หน้าเว็บจะแสดงคำตัดสิน เหตุผล ค่าของแต่ละเทคโนโลยี ภาพหลังจัดแนว และภาพเส้น SIFT/RANSAC

### วิเคราะห์หลายภาพ

เลือกหลายไฟล์หรือทั้งโฟลเดอร์ได้สูงสุด 5,000 รูปต่อครั้ง รูปละไม่เกิน 5 MB และขนาดไฟล์รวมไม่เกิน 1,000 MB ปัจจุบันหน้าเว็บส่งไฟล์ทั้งหมดเป็น request เดียว จากนั้น AI worker จึงสร้าง embedding เป็น batch และตรวจ Candidate เป็นชุด งานยังทำต่อเมื่อเปลี่ยนหน้า และหน้าเว็บเชื่อมกลับไปยังงานเดิมได้

FAISS และ pHash เป็นช่องค้นหา Candidate แยกกัน: FAISS เลือกภาพที่ embedding ใกล้เคียง ส่วน pHash สร้าง query ชั่วคราวสี่มุมแล้วค้นค่าใกล้เคียงจาก BK-tree หนึ่งต้นต่อหนึ่งงานวิเคราะห์ จึงไม่ต้องวนเทียบ pHash กับภาพทุกภาพ ค่า pHash ที่เก็บในฐานข้อมูลยังเป็นมุมปกติเพียงค่าหนึ่งต่อภาพ และ SIFT/RANSAC ยังคงเป็นผู้ยืนยันผลจริง

### กลุ่มภาพสัมพันธ์

กลุ่มย่อยเกิดจากความสัมพันธ์ที่ตรวจพบจริง ส่วนชื่อไฟล์รูปแบบ `home_<เลข 10 หลัก>` หรือ `splitter_<เลข 10 หลัก>` ใช้รวมกลุ่มย่อยไว้ใต้กลุ่มใหญ่เดียวกันเพื่อให้อ่านง่าย โดยไม่สร้างความสัมพันธ์ปลอม

เมื่อชี้แถวความสัมพันธ์ ภาพคู่ด้านบนจะยกขึ้นพร้อมกรอบเขียวและส้ม กดแถวเพื่อเปิดคู่นั้นในหน้าเปรียบเทียบ

## หมายเหตุเรื่องฐานข้อมูลและ Production

ค่าเริ่มต้นใน `config/default.yaml` ใช้ SQLite ที่ `data/app.db` และโหมด `JOBS__WORKER_MODE=process` ทำให้ API เปิด AI worker เป็น process แยก แต่ทั้งสอง process ยังใช้ฐานข้อมูล SQLite เดียวกัน การตั้งค่า Docker Compose เป็นอีกโหมดหนึ่ง: API และ Celery worker เชื่อม PostgreSQL/Redis และแชร์ volume ภาพ การเปิด Compose ไม่ได้ย้ายข้อมูลจาก SQLite ให้อัตโนมัติ จึงต้องวางแผน migration ก่อนสลับฐานข้อมูล ดูรายละเอียดใน [production.md](production.md)

SSCD อาจต้องดาวน์โหลดโมเดลครั้งแรก หากเครื่องไม่มีอินเทอร์เน็ตต้องเตรียมไฟล์ไว้ล่วงหน้า ระบบไม่ใช้ paid API สำหรับการวิเคราะห์ภาพ
